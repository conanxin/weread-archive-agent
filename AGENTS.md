# Agent Instructions / Hermes + OpenClaw

Project: WeRead Archive Agent (personal local ebook workflow)

## Contract

- Use `python wereadlab.py ... --json` from the repository directory. JSON status values are stable for downstream orchestration; never parse Chinese terminal prose as state.
- First call `doctor --json`. If `NEEDS_SETUP`, ensure Git and Python exist. `login` requires an interactive browser on the Windows desktop. Do not request, read, print, transmit, or commit raw cookies.
- Accept only an actual `https://weread.qq.com/web/reader/...` URL supplied by the user, or resolved by a separate permitted book-discovery integration; never assume `bookDetail` IDs are interchangeable.
- Before any full-book export, run `python wereadlab.py catalog URL --json` to obtain an authenticated local catalog snapshot.
- If a chapter has `CONTENT_SUSPICIOUS` due to image-only EPUB but provider wordCount suggests substantive text, use the TXT fallback built into the worker after verification; never mark the EPUB-only tiny text as complete. Preserve the original EPUB checkpoint and report recovered `txt_fallback_ordinals` for visual QA.
- After a real authenticated `CATALOG_READY`, save the returned book-specific private directory. Call `python wereadlab.py queue init --catalog <this-book-dir>/catalog.json --json` and `python wereadlab.py queue status --db <this-book-dir>/chapters.sqlite --json`. `QUEUE_READY` means only task metadata is stored; no text has been fetched. Do not use `--latest` for a new-book workflow when other books are already present; always pin that book's directory and ID.
- Start with `python wereadlab.py queue run --db <this-book-dir>/chapters.sqlite --limit 1 --json` and inspect a real substantive chapter. If earliest items are front matter only, use bounded `export URL --sample 2 --skip N --format epub --format md --json` on a mid-book chapter, not a whole-book shortcut. Stop and classify `WORKER_BLOCKED`, `WORKER_PARTIAL`, or `COMPLETED_ARTIFACT_INTEGRITY_ERROR` before retrying.
- After the pilot passes, resume with bounded `queue run --db <this-book-dir>/chapters.sqlite --limit 4 --json` calls and inspect the same queue until all eligible chapters are COMPLETE. Never use `export --full` as a shortcut; avoid aggressive concurrency or reading raw cookie values.
- If chapter text is preserved but image assets fail, repair the **specific current book's** preserved `.partial.epub` with the scoped image-repair routine, instead of re-fetching chapters or using `--latest` across multiple books. Do not disclose cookie values or book text. No success claim if `IMAGE_ASSETS_INCOMPLETE` remains.
- Preserve source H1/H2 and avoid hardcoded cross-book title deletion. For a proven original H2 secondTitle, use a separate v4-headings candidate; for an original H2 class=txtheading-1-15 with nonempty id after an exporter-generated plain H1, explicitly choose the isolated v5-headings candidate and cached_source_parity --heading-policy v5. Original H2 must exactly match frozen catalog, no intervening content. Previous v2/v3/v4 policies remain unchanged; source-reader visual and human sign-off are separate.
- For heading-fidelity experiments, first run `python -m tools.heading_fidelity --book-dir <private-book-dir>` read-only. Only with explicit candidate intent use `--build-versioned`; never overwrite delivered EPUB/PDF or chapter checkpoints. Separate local candidate QA, source reader visual review and owner-only Drive upload as distinct gates.
- To audit source-to-artifact text parity, run `tools/source_parity_audit.py` with explicit `--live` and no more than six selected chapter ordinals. Default to TXT recovered late chapters; do not print content, screenshots, raw URLs, credentials or remote response bodies. A same-upstream re-fetch is not independent visual fidelity proof. Store only metrics under `.local` and return explicit mismatch statuses.
- Before assembling, run `python -m tools.preassembly_risk_audit --book-dir <this-book-dir> --output .local/preassembly-risks.json` on the existing queue (works mid-capture): check low body-text/provider-word ratio and unreferenced large map/illustration assets. Treat both as review triggers; inspect original reader/TXT source and combine text + genuine original image only with exact evidence. Explain unresolved estimate-only metadata warnings. Do not treat a finished queue or valid EPUB CRC alone as complete visual fidelity.
- Only after all rows are COMPLETE, SHA checks pass, and preassembly risks are resolved or documented, call `python wereadlab.py book assemble --db <this-book-dir>/chapters.sqlite --format epub --format md --format pdf --format txt --json`. Never use `--latest` when handling multiple books. If Calibre renders hundreds of HTML chapters, the remote shell wrapper may finish before `ebook-convert.exe`; wait for actual converter process exit, valid output PDF and book-level QA rather than launching a duplicate conversion. CSS decorative warnings, catalog coverage, page layout and human approval are separate gates.
- For any versioned/deduplicated EPUB candidate, run `python -m tools.cached_source_parity --book-dir <private-book-dir> --compiled <candidate.epub> --heading-policy <v3-or-v4-or-v5-matching-source> --output .local/parity-receipt.json` before asserting cached-source fidelity. Require `P3H_CACHED_SOURCE_PARITY_PASS`; choose heading policy based on proven actual markup, not blindly v4. This compares frozen local chapter EPUBs with the assembled version, not current live reader layout, publisher-master text, or human acceptance.
- When a book contains converted Images/note.png alt annotations, run `python -m tools.note_fidelity --book-dir <private-book-dir> --compiled <candidate.epub> --heading-policy <v3-or-v4-or-v5-matching-actual-source> --pdf <candidate.pdf> --output .local/note-fidelity-receipt.json`. Require `P3J_NOTE_TEXT_ANCHOR_PASS` for source text and body/block anchor fidelity, never equate it with source-reader popup interaction or human visual acceptance. Online reader DOM note order is not guaranteed to equal EPUB note order.
- P3-K reader preference: full inline annotation text is accepted for this personal reading workflow. Keep the existing versioned EPUB/PDF as the preferred reading candidate; do not create an interactive popup-only release or demand original-reader popup UI equivalence unless the user explicitly changes this preference. When --pdf is supplied, verify all note text occurrences including duplicate counts via tools.note_fidelity; distinguish note-style acceptance from a full-book human reading sign-off.
- Cross-book intake (four completed): follow `docs/P4H_FOUR_BOOK_POSTMORTEM_FIFTH_PLAYBOOK.md`; earlier third/fourth target-pending pages are historical snapshots, not current instructions. The fifth book needs the user's actual authorized `https://weread.qq.com/web/reader/...` URL before catalog/text acquisition. Never reuse prior IDs, queue, source directory or Drive parent. New-book headings, illustrations, image-only sections and TXT fallback are evidence-specific, not fixed 22/66/602/146 counts or blindly forced v4/v5 rules.
- Do not claim complete just because the CLI returns `FILES_READY_COMPLETENESS_UNVERIFIED`. Compare the reader catalog, check front/middle/end and image references. Ask the user only for steps that truly require a person.
- If `LOGIN_REQUIRED`, `MANUAL_VERIFICATION_REQUIRED`, `WEB_UNAVAILABLE`, or `ACCESS_RESTRICTED`, stop that book and report a succinct blocker. No captcha bypass, simulated user identity, fingerprint evasion, high-rate retry loops, or scraping inaccessible pages.
- `upstream --update` is an explicit controlled step, not performed before every export. Record SHA and re-run the fixture tests and 2-chapter sample after updates.
- Before reporting a private cloud delivery, prepare an allowlisted manifest with `tools.private_release_manifest`; require existing `tools.private_release_verify` to return `PRIVATE_DELIVERY_PASS` from real cloud IDs, correct parent folder, exact bytes, owner-only permissions and independently downloaded cloud SHA256. It is a verifier, **not an uploader**; do not create a second bespoke delivery gate. Real cases C and D had EPUB mistakenly uploaded to Drive root despite UI success: locate its exact ID, move that file to the intended private folder, then re-check metadata and full downloaded SHA. A non-200 response from one cloud download URL (e.g. TXT) is an unresolved readback, not content corruption; retry an authorized alternate Drive download endpoint, verify actual bytes and keep both receipts.
- Never commit/export credential files, copyrighted book contents, screenshots of real book chapters, or real user metadata into this public repository.
- External GUI/browser/login execution is on the user's authorized local computer only. GitHub Actions must only use synthetic fixtures and public repository metadata.
