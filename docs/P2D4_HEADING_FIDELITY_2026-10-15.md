# P2-D4 · Provenance-gated heading audit and versioned book candidate

Date: 2026-10-15. Evidence is aggregate and anonymized; no private book text, user cookies, reader URLs, image assets or the actual book files are in this repository.

## 1. Causal finding

The pinned upstream `make_chapter_xhtml()` unconditionally writes a plain unstyled leading `<h1>title</h1>` before the extracted source XHTML body. Some source chapters also begin with their own H1 bearing the same title. The original 275-page PDF consequently has, for some chapters, an extra nearly-empty synthetic title page.

Source-local audit of all 22 per-chapter EPUBs found **12** exact consecutive duplicates at ordinals **2, 3, 5, 6, 8, 9, 11, 12, 14, 15, 17, 18**. Earlier draft Issue #23 accidentally listed ordinal 1 instead of 3; this report corrects the sequence with a reproducible stricter rule.

The removal criterion is deliberately narrow: the first element after `<body>` must be the **literal unstyled H1 generated by the upstream exporter**, matching the frozen catalog title; it must be immediately followed by an original H1 with the same normalized title. No intervening substantive text or images are allowed. Do not apply this as a general "delete duplicate headings" rule or remove authentic source H1.

## 2. Implementation & review

- Merged [PR #25](https://github.com/conanxin/weread-archive-agent/pull/25) introduces `tools/heading_fidelity.py` (read-only by default).
- Command used for read-only audit:
  `python -m tools.heading_fidelity --book-dir .local/library/<PRIVATE_BOOK_ID>`
- An explicit `--build-versioned` writes *only* `.local/library/<PRIVATE_BOOK_ID>/final/v2-headings/book.epub`. It refuses to overwrite an existing candidate.
- Original source SHA256 is checked against the private saved `fullbook_QA_report.json` before any edits; private 22-chapter SQLite queue/candidate source hashes must match. Source chapter checkpoints and original `final/book.epub` and `book.pdf` are not overwritten.
- The tool checks that all unchanged EPUB ZIP entries retain identical uncompressed bytes, that there are still 22 spine chapters and no image-reference regression; it writes a private `headings_qa.json`.
- Offline regression tests cover positive narrow H1 removal, mismatch/different headings, intervening text/image, non-overwrite, source-SHA failure, and ZIP integrity. **Linux 54/54**, **Windows CI 54/54** and **actual Windows local 54/54 PASS**.

## 4. Visual evidence

A private five-pair contact sheet compares representative original and v2 PDF pages near front matter, an illustrated body chapter, the end of the main text, the conclusion, and the references. Original synthetic-title pages use most of the sheet for heading + whitespace. In the candidate, an original source heading and its body flow together. End-matter conclusion and reference pages visually remain normal.

**Limit:** Five-pair QA and programmatic checks cannot prove every caption, note layout and source-reader screenshot match. This candidate is still **FIDELITY_UNVERIFIED**, not `FULL_BOOK_CONFIRMED`.

## 6. Reusable lessons

1. The correct unit of cleanup is the **provenance-identified synthesized node**, not an apparently redundant string. Source text should remain untouched.
2. Check chapter order and source SHA **before** visual processing; text-only and structural invariants do not replace original visual review.
3. A twelve-page reduction may be desirable while all 166 embedded PDF image objects are preserved; nonetheless a page-count change alone never proves fidelity.
4. Treat local candidate generation, machine QA, private Drive upload and reader acceptance as four independent gates.
5. Use `python -m tools.heading_fidelity` from repository root; direct `python tools/heading_fidelity.py` does not resolve package imports in some Python environments.
